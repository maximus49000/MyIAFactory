# Le modèle par tâche, la fiche comme plafond — conception (2026-11-12, suite de `2026-11-12-recrutement-design.md`)

Décision du Directeur : « Chaque agent sera donc un agent Opus de base, MAIS il fera tourner le modèle nécessaire pour faire tourner la tâche, ni plus ni moins. C'est donc aussi le cas des agents locaux. »

1. **Le modèle nécessaire** est une propriété de l'étape (`orchestrateur/modele_necessaire.py`, pur) : `modele` (Haiku/Sonnet/Opus, jamais Fable) et sa `justification` sur l'étape du flux, posés par `proposer_organisation` / `definir_workflow` (facultatifs : validés s'ils sont là) ; à défaut **déduit** de la nature de l'étape (nom puis id, puis rôle : la table `_NATURES` du recrutement — conception/architecture → Opus, tests/vérification/livraison/rangement → Haiku, code/création → Sonnet) ; nature inconnue → le modèle du rôle (première fiche, Fable compté Opus), comme le recrutement. Les workflows existants sans `modele` par étape sont déduits à la lecture, sans migration.
2. **Tâches hors flux** : relecture, correction, retour, demande → l'étape de leur rôle dans le workflow de leur fonctionnalité ; **cadrage, prototype, installation : le modèle de la fiche de l'agent, comme aujourd'hui** (décision : la qualité du cadrage et du prototype conditionne tout le reste ; un agent de cadrage recruté en Opus cadre donc en Opus).
3. **Montée** (échec, cadrage d'un agent Haiku) : `montee.a` remplace le modèle nécessaire de la tâche ; toujours ramenée au plafond.
4. **Plafond** = modèle de la fiche, pour un agent local comme cloud : il prend toute tâche de son rôle dont le modèle nécessaire est ≤ son plafond et la fait tourner **exactement** sur ce modèle ; jamais au-dessus. Le plus petit plafond suffisant d'abord (`agent-libre` avec `modele` = modèle nécessaire, `sans_session` idem).
5. **Jamais bloqué** : si aucun agent du rôle n'a un plafond suffisant (projet existant : agents Sonnet, étape déduite Opus), le modèle nécessaire est ramené au plus haut plafond du rôle — la tâche part comme avant au lieu d'attendre une recrue qui ne viendra pas ; le bureau montre « ramené au plafond ».
6. **Lots** (`lancer lots`) : un lot regroupe des tâches du même modèle nécessaire (et du même lieu : celui du plus petit plafond suffisant) ; le moteur passe ce modèle au choix d'agent et au départ.
7. **Recrutement** : plafond Opus par défaut partout (sélecteur manuel ; auto : le « modèle le plus logique » devient `modele_necessaire` affiché, la recrue a le plafond Opus ; workflow proposé : agents en Opus, `fable_suggere` inchangé ; Fable seulement avec l'accord du Directeur). Agents déjà recrutés : leur fiche ne change pas, son modèle devient leur plafond.
8. **Estimation** : `estimation.estimer` prend le modèle nécessaire de chaque étape (plus celui de l'agent) ; usages et facturation notent déjà le modèle réel de chaque appel (inchangés).
9. **Bureau** : fiche d'un agent « Plafond : Opus » ; tâche « Modèle nécessaire : Sonnet (raison) » (`modele_necessaire` au relevé) ; Parallélisme : une ligne de règle.
10. **Mesure** : tests Python (module, `agent-libre`, `lots`, moteur local et cloud, jugements, recrutement, estimation, relevé) et `node --test` ; banc rejoué inchangé pour un projet à un agent du bon modèle ; aucun appel réel.
