# Recruter des agents depuis le bureau — conception (2026-11-12, suite de `2026-11-12-parallelisme-design.md`)

1. **Où** : la partie « Parallélisme du projet » (onglet Facturation) ; le relevé publie `recrutement` `{roles, places, depot, cloud_impossible, propositions}`, calculé par `orchestrateur/recrutement.py` (pur, sans IA).
2. **Manuel** : rôle (rôles des étapes d'agent des workflows du projet) + modèle (Haiku/Sonnet/Opus ; Fable seulement si la case « J'accorde Fable » est cochée, la fiche porte l'accord daté) + lieu → demande `recruter` `{mode: "manuel", agents: [1 agent]}`.
3. **Fiche** : clé `<rôle>-<n>` libre, premier prénom de l'équipe (`bureau/equipe.PRENOMS`) pas encore pris, service et texte d'une fiche du même rôle (sinon de l'étape), même brief `briefs/<rôle>.md` (exigé). Écrite par `lancer recruter` seulement (tout ou rien).
4. **Auto** : « Recruter N agents » → les N premières `propositions` (gloutonnes, donc identiques quel que soit N) : à chaque pas, le rôle dont le travail non couvert (tâches prêtes non bloquées + éléments en file qui passeront par son étape avant la première validation, moins ses agents et recrues) est le plus grand, à égalité l'ordre du workflow ; les tâches de flux retenues par une validation-barrière non franchie ne comptent pas.
5. **Modèle auto** = celui de la première fiche du rôle (Fable → Opus : un outil ne choisit jamais Fable), sinon Sonnet. **Lieu auto** = cloud tant que `agents_cloud_max` − cloud recrutés > 0 et projet sur GitHub, sinon local tant que `agents_locaux_max` − locaux recrutés (hors chef) > 0 ; jamais au-delà ; chaque ligne porte sa raison. Aperçu, puis « Confirmer » → `recruter` `{mode: "auto", agents}`.
5 bis. **Lieu demandé et modèle selon le travail** (suite) : le formulaire auto prend N et un lieu `mieux` (le comportement ci-dessus), `cloud` ou `local` (agents de ce lieu seulement, dans ses places ; N trop grand → la page dit combien sont possibles ; sans GitHub → la raison et « Créer le dépôt Git »). Le relevé publie `propositions_par_lieu`/`notes_par_lieu` ; la demande `recruter` porte `lieu`, revérifié par le serveur et l'outil. Le modèle de chaque recrue vient du travail qu'elle prend (`modeles_du_travail`) : nature de l'étape ou du titre (conception/architecture → Opus ; vérification/tests/livraison/rangement → Haiku ; code/création/contenu → Sonnet), une tâche relancée après échec, déjà montée ou renvoyée « À revoir » au moins deux fois monte d'un cran (Opus au plus), nature inconnue → modèle du rôle ; jamais Fable ; la raison est affichée.
6. **Plafonds vérifiés trois fois** (page, serveur contre le relevé, outil contre les fiches) : cloud toujours ≤ places cloud libres ; local plafonné en auto seulement (un spécialiste de plus n'ajoute pas de parallélisme au-delà de `agents_locaux_max`).
7. **Cloud ⇔ GitHub** : lu dans `.git/config` (remote `origin` sur github.com), sans lancer git. Sans dépôt : lieu cloud désactivé avec la raison, bouton « Créer le dépôt Git » → demande `depot_git` `{confirme: true}` (le clic = consentement) → `lancer depot` : `.gitignore` réglé (`regler_gitignore` : `.env`, fichiers propres au poste ; `.factory` versionné, convention de l'installation), `git init` + premier commit si besoin, dépôt GitHub **privé** par `creation.github`/`gh repo create --private --source . --push` ; résultat (lien ou raison + commande) noté dans `depot-git.json` et publié. Une origine non GitHub n'est jamais remplacée.
8. **Après** : automatique — le moteur choisit l'agent cloud libre quand une tâche part, pousse, lance `claude --cloud`, relève par le dépôt et fusionne. Manuel — si le lancement échoue deux fois (claude absent ou non connecté, accès GitHub de Claude Code pour le web), la tâche est bloquée et la décision « Sessions cloud à créer » (`session_cloud`) est posée avec la démarche ; « C'est fait » inscrit la session et remet les tâches bloquées de cet agent en route.
9. **Refus** clairs à chaque étage ; aucune création de dépôt sans clic ; aucun appel d'IA.
10. **Mesure** : tests Python (outil, moteur, bureau) et `node --test` (aperçu, demandes) ; git/gh uniquement simulés.
